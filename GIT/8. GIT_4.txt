

Local to remote: 

- git init																					: initialize an empty repository used only when creating a new repository 
- git add																						: will move the items to the staging area (at first means, start tracking them)
- git add src/  or git add . 
- git commit																				: will pass the staged changes to the local repository
- git commit --amend -m "Your new commit message"		: RENAME the last commit
- git restore .																			: means turn to the previous state. so basically discard changes. (git restore .)
- git revert HEAD																		: it will revert the last commit and commit it 
- git remote add origin <url>												: adds the origin (remote location)
- git branch -M main																: rename the master branch to main 
- git push -u origin main														: push the changes to the remote and track the origin/main branch
- git diff 																					: shows the differences that has made
- git pull origin main															: WE WILL USE THIS A LOT!!! 
			When everyone pushes something to their branches and merge them with main, we pull the changes from the main.
			When I do GIT PULL ORIGIN MAIN, I am getting the changes on my current branch from the remote MAIN branch.
			We specify that we want the updates from the MAIN. That's why we say 'origin main'. REMOTE MAIN.
						
						


Remote to local: 

- git clone <repo url>: it will clone the repository in the current folder

- git pull: 	it will get the changes from remote repository to the local 
				repository and working area

- git fetch:	it will only update the local repository


- git stash  							--> only tracked changes
- git stash -u  						--> stash tracked and untracked changes ( stash ALL OF THEM !! like -> add .)
- git stash -m "feature in progress" 	--> stash tracked changes with a message
- git stash git stash apply stash@{0} 	--> if there is more than one stashes, we can choose which one we call back
- git stash list						--> tum stash'leri listeler

	CONFLICT ---> 	Iki kisi ayni anda, ayni linelar icine kod yazip push ederse, cakisma oluyor. Buna da CONFLICT deniyor.
	
	Conflict olustugunda, conflict olusan kisi ile iletisime gecip kodlari karsilastirmak gerekiyor. 
	Once kendi kodumuzu git stash yapariz ve daha sonra git pull yapilir ki karsi tarafin kodlari cekilir. 
	
	karsi tarafin kodlarini cektikten sonra, git stash pop yaparak, kendi degisikliklerimizi karsi tarafin degisiklikleri ile birlestiririz.
	
	"conflict olustu, degisikligin kalsin mi, ne yapalim? gibi iletisime gecilir.
	Aramizda cozdukten sonra duruma gore eclipse'de olusan conflict uyarilari temizlenir. 
	KENDI BRANCH'imize git add. / git commit -m / git push ve git pull request yapilir. Ve git merge yapilir.
	
	Tum degisiklikler yapildiktan sonra, Conflict cozuldukten sonra, main branch'e checkout yapilarak uzerinde calistigimiz 
	BRANCH silinir. 
	git pull ile tum yapilan degisikler cekilerek local main 'imiz update edilir ve guncel hale gelinir.

	YANLISLIKLA main'de commit edilen bir degisikligi, baska bir branch'e aktarma !!!
	
	*If you’ve committed to the main branch by mistake and want to move the commit entirely to a new branch:
	
		1. Create and switch to a new branch from the current commit:
			git checkout -b new-branch-name
			
		2. Push the new branch to the remote:
			git push origin new-branch-name
			
		3. Go back to main and reset it: If you want to remove the commit from main, go back to main and reset it to the previous commit:
			git checkout main
			git reset --hard HEAD~1
			
		4. Push the reset state of main to the remote: This will remove the commit from main on the remote repository as well:
			git push origin main --force
		
	* This way, the commit will exist only on the new branch and not on main.

	- made some changes

	- fixed the conflict

	what should we do now???

		to update we do: git pull origin main (because this means, get changes from main into sabahBranch)

	then we move to the main branch (git checkout main)
		to update we do: git pull (by default local main pulls from origin/main)
