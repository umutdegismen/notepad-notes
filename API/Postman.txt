//	
//		1.Http method 	-> GET/POST/PUT/PATCH/DELETE

//		
//		1.Status Code
//		2.Header		-> List of things such as "Content-Type=json" (Date,Server,Content-Encoding etc.)
//		3.Response Body -> The result body of what we request.

//						   "result":{
//								"items":[

IDEMPOTENT in API:
    
    Idempotent : Getting the same result over and over again with sending the same request.
                 As long as we send the request, we will get the same result. That's why, GET method is an IDEMPOTENT method.
   
    GET request     -> Idempotent
    POST request    -> NOT Idempotent
    PUT request     -> Idempotent (In general PUT request is Idempotent depends on how developers develope API)
    DELETE request  -> Idempotent (In general DELETE request is Idempotent depends on how developers develope API. 
                                   For example, first time I delete something it says OK, second time I try to delete the same thing it says "There is no such element to delete")

	Authorization:
	
		When we try to get the data in Students class, we will have Authorization problems. 
		
		We have to authorize ourselfs in Postman by creating token authotentication.
		
		-Copy the URI 'TokenAuth' from swagger and create a POST request in Postman in Authorization section.
		
		-Provide the data for in 'Body/raw/JSON' in Postman 
			{
			  "userNameOrEmailAddress": "Tester",
			  "password": "Student@Neo",
			  "rememberClient": true
			}
		
		-Copy the 'accessToken' 
		-Go back to 'Get All Students' request and paste the token in Authorization section.
		-Select 'Bearer Token' in 'Type' section and paste the token you've copied and click 'Send'.

		*** The token will be available 24h ***

	Parameters:
	
		API Documentations tells us if we need to nse 'Path Parameters' or 'Query Parameters'
	
		PATHS Parameters:
	
			Id *
			integer($int32)
			(path)				----> TELLS US IF IT IS PATH Parameter OR QUERY Parameter
			
				If you see {id} in uri like: "/api/services/app/Class/Get/{Id}"
				
				That means we need to give a parameter to see the data such as "/api/services/app/Class/Get/327"
				
				When it is a PATH parameter, we use "/" at the end of api: /Get/327
				
				Part of the URL path itself. We send the parameter at the end of the Uri / Endpoint
				Used to specify a data like ID. (Mandatory Data) (getStudent/Id=337)
		
		QUERY Parameters:
			
			Id
			integer($int32)
			(query)				----> TELLS US IF IT IS PATH Parameter OR QUERY Parameter
			
				If it needs a QUERY parameter, we need to send a QUERY parameter like: "/api/services/app/Student/Get?id=317"
				
				When it is a QUERY parameter, we use "?" at the end of api: /Get?id=317
				
				We send the parameter at the end of the Endpoint by using '?' 
				
				Usually used for optional filters or configurations.
				Used to filter, sort, or modify the data (Optional Data)
